# PRD: 单元测试重构 - 第四阶段 (性能与稳定性优化)

## 1. 背景与目标

目前的测试代码中大量使用了 `setTimeout` 进行固定时间的等待（例如等待重试、等待任务完成），这导致：

1.  **测试运行缓慢**：大量无意义的空闲等待时间。
2.  **结果不稳定 (Flaky)**：如果机器负载高，`setTimeout` 可能结束了但 Redis 操作还没完成，导致断言失败。

**目标**：

- 将 `setTimeout` 替换为事件驱动的 `waitUntilFinished` 或状态轮询 `waitForEmpty`。
- 将测试中的 `backoff`（退避时间）、`delay`（延迟时间）和 `interval`（轮询间隔）缩短到毫秒级（10ms-50ms）。

## 2. 优化任务清单

### 任务 2.1: 优化 `resilience/retry-mechanism.test.ts`

该文件测试重试逻辑，目前可能使用了默认的长时间退避。

- **修改点 1**: 在初始化 `Worker` 时，自定义 `backoff` 策略。
  - **Before**: 可能未设置（默认指数退避）或设置了较长时间。
  - **After**: 设置为 `() => 10` (固定 10ms)。
- **修改点 2**: 移除 `setTimeout` 等待。
  - **Before**: `await new Promise(r => setTimeout(r, 1000))` 等待重试完成。
  - **After**: 使用 `await queue.waitForEmpty()` 确保所有重试尝试都已执行完毕。

### 任务 2.2: 优化 `resilience/stalled-worker.test.ts`

该文件测试卡死任务的检测，依赖于时间窗口。

- **修改点 1**: 缩短检测间隔。
  - **Before**: `stalledInterval: 30000` (30 秒)。
  - **After**: `stalledInterval: 100` (100 毫秒)。
- **修改点 2**: 调整测试逻辑中的等待。
  - **Before**: `setTimeout(..., 1000)`。
  - **After**: 使用轮询检查或较短的 `setTimeout` (如 200ms)，只要大于 `stalledInterval` 即可。

### 任务 2.3: 优化 `resilience/graceful-shutdown.test.ts`

该文件测试 Worker 关闭时是否能完成当前任务。

- **修改点**: 缩短模拟任务的时长。
  - **Before**: 模拟任务耗时 `1000ms` 或 `2000ms`。
  - **After**: 将任务耗时改为 `50ms` - `100ms`。这足以模拟“正在运行”，但不会显著拖慢测试。
  - 相应地，`worker.close(timeout)` 的超时参数也可以缩短。

### 任务 2.4: 优化 `features/scheduling.test.ts`

该文件测试延迟任务和 Cron。

- **修改点**: 缩短延迟时间。
  - **Before**: `delay: 1000` 或 `delay: 5000`。
  - **After**: 改为 `delay: 100` 或 `delay: 200`。
  - **注意**: 必须确保 `queue` 的 `schedulerLockTtlMs` 和 Worker 的 `schedulerIntervalMs` 也相应调小（例如 50ms），否则调度器扫描不到过期的任务。

### 2.5: 优化 `features/batching.test.ts`

该文件测试批量处理。

- **修改点**: 替换固定等待。
  - **Before**: `await new Promise((resolve) => setTimeout(resolve, 3000));`
  - **After**: `await queue.waitForEmpty();`。如果必须等待批处理缓冲刷新，可以使用 `await new Promise(r => setTimeout(r, 20));` (略大于 `maxWaitMs` 默认值 10ms)。

## 3. 具体修改示例 (Reference)

### 关于 `waitUntilFinished` 的使用

- **成功预期**: `const result = await job.waitUntilFinished(5000);`
- **失败预期**: `await expect(job.waitUntilFinished(5000)).rejects.toThrow();`

### 关于 Worker 配置优化

在测试中创建 Worker 时，请统一应用极速配置：

```typescript
const worker = new Worker({
  queue,
  // 极速清理，避免测试结束时还在清理导致句柄泄漏
  cleanupIntervalMs: 100,
  // 极速调度，让 delayed 任务立刻被发现
  schedulerIntervalMs: 50,
  // 极速处理，减少阻塞等待
  blockingTimeoutSec: 0.1,
  // ... handler
})
```

## 4. 验证标准

1.  **速度**: 全量测试运行时间应显著减少（例如从 3 分钟 -> 30 秒以内）。
2.  **稳定性**: 连续运行 5 次 `npx vitest run`，应全部通过，无 Flaky 失败。

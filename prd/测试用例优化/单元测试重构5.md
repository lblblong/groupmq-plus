# 🚀 测试架构重构 PRD：智能资源管理

## 1. 目标

将所有集成测试迁移到增强版 `tests/helpers/suite.ts`。新架构通过工厂模式 (`createQueue`, `createWorker`) 实现了资源的**自动依赖注入**和**自动生命周期管理**，彻底消除了手动关闭资源 (`.close()`) 和清理数据的样板代码。

## 2. 涉及范围

`tests/` 目录下所有 `.test.ts` 文件。

## 3. 核心变更规则

### 3.1 引入 (Imports)

- **统一入口**：所有测试工具 (`test`, `expect`, `describe` 等) 必须从 `tests/helpers/suite` 导入。
- **移除**：移除 `createRedis` 和 `ioredis` 的导入（除非测试极其特殊需要原生 Redis 操作）。

### 3.2 模式迁移 (Patterns)

#### 场景 A：标准 CRUD 测试 (最简单)

如果只需要一个默认配置的队列，直接解构 `queue`。

**Old:**

```typescript
it('basic test', async () => {
  const q = new Queue({ redis, namespace })
  await q.add({})
  await q.close()
})
```

**New:**

```typescript
test('basic test', async ({ queue }) => {
  // queue 已自动创建，测试结束后会自动关闭
  await queue.add({})
})
```

#### 场景 B：自定义队列配置 (如 autoBatch)

使用 `createQueue`。**无需手动传递 redis 或 namespace**，除非你想覆盖默认行为。

**Old:**

```typescript
it('batch test', async () => {
  const q = new Queue({ redis, namespace, autoBatch: true })
  await q.add({})
  await q.close()
})
```

**New:**

```typescript
test('batch test', async ({ createQueue }) => {
  // redis 和 namespace 会自动注入
  const q = createQueue({ autoBatch: true })
  await q.add({})
  // 无需调用 q.close()，Fixture 会自动处理
})
```

#### 场景 C：使用 Worker

使用 `createWorker`。**无需 `try...finally` 块** 来关闭 Worker。

**Old:**

```typescript
it('worker test', async () => {
  const w = new Worker({ queue, handler: ... });
  try {
    w.run();
    // assertions
  } finally {
    await w.close();
  }
});
```

**New:**

```typescript
test('worker test', async ({ queue, createWorker }) => {
  // Worker 会在测试结束时自动关闭
  const w = createWorker({
    queue,
    handler: async (job) => { ... }
  });

  w.run();
  // assertions...
});
```

#### 场景 D：多个 Queue 或 Worker

工厂方法可以调用多次，所有创建的实例都会被追踪并自动清理。

**New:**

```typescript
test('multi-queue', async ({ createQueue, createWorker }) => {
  const q1 = createQueue();
  const q2 = createQueue(); // 完全隔离的实例，但共享同一个 namespace 用于测试交互

  const w1 = createWorker({ queue: q1, ... });
  const w2 = createWorker({ queue: q2, ... });

  // 测试逻辑...
  // 结束时：w2 close -> w1 close -> q2 close -> q1 close -> redis disconnect
});
```

## 4. 给 AI 的执行指令

> 请根据上述 PRD (v2.0)，重构 `tests/` 下的所有测试文件。
>
> **关键指令：**
>
> 1.  将 `import { ... } from 'vitest'` 替换为 `import { test, expect, describe, ... } from '../helpers/suite'` (注意相对路径)。
> 2.  将 `it(...)` 替换为 `test(...)`。
> 3.  **移除** 所有 `beforeAll`, `afterAll`, `beforeEach`, `afterEach` 中关于 Redis 连接创建/销毁和 Key 清理的代码。
> 4.  **移除** 所有手动的 `queue.close()` 和 `worker.close()` 调用。
> 5.  **移除** 所有 `try...finally` 块用于关闭资源的代码。
> 6.  如果是简单场景，解构 `{ queue }`。
> 7.  如果是自定义配置场景，解构 `{ createQueue }` 并替换 `new Queue(...)`。
> 8.  如果有 Worker，解构 `{ createWorker }` 并替换 `new Worker(...)`。
> 9.  保持测试内部的逻辑（添加任务、断言等）不变。
